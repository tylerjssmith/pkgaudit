# pkgaudit Rule Coverage

pkgaudit v0.3.0 separates *when* code executes from *what* code does using three categories of rules: file contexts, code contexts, and patterns. Each rule is defined in a YAML file under [inst/rules/](inst/rules/) and compiled into the SQLite database at `inst/db/rules.db`. The Rule columns below link to the defining YAML files.

## File Contexts

File contexts are files that R executes at build-, check-, or install-time.

| Rule | File Context | Description |
|---|---|---|
| [cleanup_file](inst/rules/file_contexts/file_cleanup.yaml) | `cleanup` | cleanup is a shell script executed after a package is installed from source on Unix-like systems. It can execute arbitrary shell commands. |
| [cleanup_win_file](inst/rules/file_contexts/file_cleanup_win.yaml) | `cleanup.win` | cleanup.win is a shell script executed after a package is installed from source on Windows. It can execute arbitrary shell commands. |
| [configure_ac_file](inst/rules/file_contexts/file_configure_ac.yaml) | `configure.ac` | configure.ac is an Autoconf input file that does not itself execute; it is processed by Autoconf to generate the configure script, which executes shell commands when a package is installed from source. |
| [configure_file](inst/rules/file_contexts/file_configure.yaml) | `configure` | configure is a shell script used for system-dependent configuration when packages are installed from source. It can execute arbitrary shell commands. |
| [configure_in_file](inst/rules/file_contexts/file_configure_in.yaml) | `configure.in` | configure.in is a legacy-named Autoconf input file that does not itself execute; it is processed by Autoconf to generate the configure script, which executes shell commands when a package is installed from source. |
| [configure_ucrt_file](inst/rules/file_contexts/file_configure_ucrt.yaml) | `configure.ucrt` | configure.ucrt is a shell script for system-dependent configuration on the Windows UCRT toolchain, executed when a package is installed from source; it takes precedence over configure.win when present. |
| [configure_win_file](inst/rules/file_contexts/file_configure_win.yaml) | `configure.win` | configure.win is a shell script for system-dependent configuration on Windows, executed when a package is installed from source. |
| [src_gnumakefile_file](inst/rules/file_contexts/file_src_gnumakefile.yaml) | `src/GNUmakefile` | src/GNUmakefile is a makefile used to compile code in src/ when a package is installed from source; GNU make reads it in preference to Makefile. It is read by make and its recipes execute arbitrary shell commands. |
| [src_install_libs_R_file](inst/rules/file_contexts/file_src_install_libs_R.yaml) | `src/install.libs.R` | src/install.libs.R is an R script used in some packages to install executable programs and other binaries during installation from source. It can run arbitrary R code. |
| [src_makefile_file](inst/rules/file_contexts/file_src_makefile.yaml) | `src/Makefile` | src/Makefile is a makefile used to compile code in src/ when a package is installed from source, replacing R's default make rules. It is read by make and its recipes execute arbitrary shell commands. |
| [src_makefile_ucrt_file](inst/rules/file_contexts/file_src_makefile_ucrt.yaml) | `src/Makefile.ucrt` | src/Makefile.ucrt is a makefile used to compile code in src/ on the Windows UCRT toolchain when a package is installed from source, replacing R's default make rules. It is read by make and its recipes execute arbitrary shell commands. |
| [src_makefile_win_file](inst/rules/file_contexts/file_src_makefile_win.yaml) | `src/Makefile.win` | src/Makefile.win is a makefile used to compile code in src/ on Windows when a package is installed from source, replacing R's default make rules. It is read by make and its recipes execute arbitrary shell commands. |
| [src_makevars_file](inst/rules/file_contexts/file_src_makevars.yaml) | `src/Makevars` | src/Makevars sets make variables used to compile code in src/ when a package is installed from source. It is read by make and can execute shell via make constructs such as $(shell ...). |
| [src_makevars_in_file](inst/rules/file_contexts/file_src_makevars_in.yaml) | `src/Makevars.in` | src/Makevars.in is a template that does not itself execute; it is processed by the configure script to generate src/Makevars, which is read by make to compile code in src/ when a package is installed from source. |
| [src_makevars_ucrt_file](inst/rules/file_contexts/file_src_makevars_ucrt.yaml) | `src/Makevars.ucrt` | src/Makevars.ucrt sets make variables used to compile code in src/ on the Windows UCRT toolchain when a package is installed from source; it takes precedence over Makevars.win. It is read by make and can execute shell via make constructs such as $(shell ...). |
| [src_makevars_win_file](inst/rules/file_contexts/file_src_makevars_win.yaml) | `src/Makevars.win` | src/Makevars.win sets make variables used to compile code in src/ on Windows when a package is installed from source. It is read by make and can execute shell via make constructs such as $(shell ...). |

## Code Contexts

Code contexts are top-level R source code and lifecycle hooks whose bodies run automatically when a namespace is loaded, attached, unloaded, or detached.

| Rule | Code Context | Description |
|---|---|---|
| [lastlib_code](inst/rules/code_contexts/code_lastlib.yaml) | `.Last.lib()` | .Last.lib() executes arbitrary code when a package namespace is detached from the R search path, e.g., by calling detach(). In modern R, this has been superseded by .onDetach(). |
| [onattach_code](inst/rules/code_contexts/code_onattach.yaml) | `.onAttach()` | .onAttach() executes arbitrary code when a package namespace is attached to the R search path, e.g., by calling library(), require(), or attach(). |
| [ondetach_code](inst/rules/code_contexts/code_ondetach.yaml) | `.onDetach()` | .onDetach() executes arbitrary code when a package namespace is detached from the R search path, e.g., by calling detach(). |
| [onload_code](inst/rules/code_contexts/code_onload.yaml) | `.onLoad()` | .onLoad() executes arbitrary code when a package namespace is loaded, e.g., by calling library(), require(), or loadNamespace(). |
| [onload_rlang_code](inst/rules/code_contexts/code_onload_rlang.yaml) | `rlang::on_load()` | rlang::on_load() registers arbitrary code to execute when a package namespace is loaded, e.g., by calling library(), require(), or loadNamespace(). on_load() requires .onLoad() to contain rlang::run_on_load(). |
| [onunload_code](inst/rules/code_contexts/code_onunload.yaml) | `.onUnload()` | .onUnload() executes arbitrary code when a package namespace is unloaded, e.g., by calling unloadNamespace() or detach(unload=TRUE). |

## Patterns

Patterns are security-relevant function calls. Each pattern finding is attributed to the code context it executes in, so a `system()` call inside `.onLoad` is distinguished from one inside an ordinary function ("Other") or at top level ("Top-level"). Qualified (`pkg::fn()`) and unqualified (`fn()`) call forms are both detected. Pattern rules carry [MITRE ATT&CK](https://attack.mitre.org/) technique labels.

| Rule | Pattern | Description |
|---|---|---|
| [curl_pattern](inst/rules/patterns/pattern_curl.yaml) | `curl()`, `curl_fetch_memory()`, `curl_fetch_disk()`, `curl_fetch_stream()`, `curl_fetch_multi()`, `curl_download()`, `curl_upload()`, `multi_download()`, `multi_run()`, `send_mail()` | A curl network call sends an outbound HTTP request or opens a connection to a remote host. A request may be used to exfiltrate credentials or other data, or to fetch a remote payload. |
| [decoding_pattern](inst/rules/patterns/pattern_decoding.yaml) | `base64decode()`, `base64_dec()`, `base64_decode()`, `memDecompress()`, `rawToChar(as.raw())` | These functions decode or decompress data. Payloads may be encoded (e.g., as base64) to evade static detection and decoded at runtime. |
| [deserialization_pattern](inst/rules/patterns/pattern_deserialization.yaml) | `readRDS()`, `load()`, `unserialize()`, `dget()` | readRDS(), load(), unserialize(), and dget() deserialize R objects or code, which can enable arbitrary code execution (CVE-2024-27322 for RDS). |
| [download_file_pattern](inst/rules/patterns/pattern_download_file.yaml) | `download.file()`, `url()` | download.file() and url() retrieve or open a connection to a remote resource. This can stage a payload for execution via source() or system() in a two-stage attack. |
| [dynload_pattern](inst/rules/patterns/pattern_dynload.yaml) | `dyn.load()`, `library.dynam()` | dyn.load() and library.dynam() load compiled code from a shared object, which executes outside the visible R source. |
| [eval_parse_pattern](inst/rules/patterns/pattern_eval_parse.yaml) | `eval()`/`evalq()` over `parse()`, `str2lang()`, or `str2expression()`, when combined with a decoding call | eval() applied to parse(), str2lang(), or str2expression() constructs and evaluates code at runtime. Here code is produced by decoding or decompression, a classic shape for executing an obfuscated payload. |
| [httr_pattern](inst/rules/patterns/pattern_httr.yaml) | `GET()`, `POST()`, `PUT()`, `PATCH()`, `DELETE()`, `HEAD()`, `VERB()` | An httr HTTP call sends an outbound request. A request may be used to exfiltrate credentials or other data, or to fetch a remote payload. |
| [httr2_pattern](inst/rules/patterns/pattern_httr2.yaml) | `req_perform()`, `req_perform_iterative()`, `req_perform_parallel()`, `req_perform_sequential()`, `req_perform_stream()`, `req_perform_connection()`, `req_perform_promise()` | An httr2 HTTP call sends an outbound request. A request may be used to exfiltrate credentials or other data. |
| [indirection_pattern](inst/rules/patterns/pattern_indirection.yaml) | `do.call()`, `match.fun()`, `getFromNamespace()`, `getExportedValue()`, `getAnywhere()`, `getFunction()`, when the first argument is a string literal | These functions resolve a function by name at runtime. A string-literal target is not a call site, so it evades pattern matching, and the namespace accessors additionally reach functions a package does not export. |
| [install_pattern](inst/rules/patterns/pattern_install.yaml) | `install.packages()`, `install_github()`, `install_gitlab()`, `install_bitbucket()`, `install_git()`, `install_url()`, `install_version()`, `install_local()`, `install_bioc()`, `install_dev()`, `install_cran()`, `pak()`, `pkg_install()`, `local_install()`, `lockfile_install()`, `BiocManager::install()`, `renv::install()`, `devtools::install()` | These functions install packages, optionally from a specified or remote source. A non-default source can introduce attacker-controlled code. |
| [options_repos_pattern](inst/rules/patterns/pattern_options_repos.yaml) | `options(repos = )` | options(repos = ...) replaces the CRAN mirror for the R session. Subsequent install.packages() calls will fetch packages from the configured repository. If set to an attacker-controlled server, this poisons the installation source. |
| [rcurl_pattern](inst/rules/patterns/pattern_rcurl.yaml) | `getURL()`, `getURI()`, `getForm()`, `postForm()`, `curlPerform()` | An RCurl network call sends an outbound HTTP request. A request may be used to exfiltrate credentials or other data, or to fetch a remote payload. |
| [socket_pattern](inst/rules/patterns/pattern_socket.yaml) | `socketConnection()`, `make.socket()`, `serverSocket()`, `socketAccept()` | These functions open a raw network socket, which may be used to exfiltrate data or receive a remote payload outside the usual HTTP clients. |
| [source_pattern](inst/rules/patterns/pattern_source.yaml) | `source()` | source() can fetch and execute local and remote R scripts. |
| [system_other_pattern](inst/rules/patterns/pattern_system_other.yaml) | `callr::r()`, `r_bg()`, `r_safe()`, `r_copycat()`, `r_vanilla()`, `rcmd()`, `rcmd_bg()`, `rcmd_safe()`, `rcmd_copycat()`, `rscript()`, `processx::run()`, `processx::pipeline()`, `exec_wait()`, `exec_background()`, `exec_internal()`, `eval_safe()`, `eval_fork()`, `r_background()`, `r_internal()`, `r_wait()`, `process$new()`, `r_session$new()`, `r_process$new()`, `rcmd_process$new()`, `rscript_process$new()` | These callr, processx, and sys functions run an external process, which may be used to execute arbitrary shell commands or a second R session outside the visible R source. |
| [system_pattern](inst/rules/patterns/pattern_system.yaml) | `system()`, `system2()`, `shell()`, `pipe()` | system(), system2(), shell() (on Windows), and pipe() execute arbitrary shell commands. |
